# disposable-build：一次性交付物构建

为「写完即弃」的交付物（demo、一次性脚本、hackathon 产物）提供最低仪式的构建纪律。

## Safety Floor（不可降级，内部决策-008）

一次性不等于无底线：默认禁生产凭据与生产数据（用合成/脱敏数据）、禁部署与共享分支写入、禁不可逆外部副作用；网络与外部写须用户显式授权；交付后临时凭据/数据须有清理或撤销证据并写入处置说明。

## 流程

1. 与用户确认处置预期：交付后归档还是删除（默认不保留）。
2. 以满足交付目的的最低成本构建；不做完整测试面，完成声称以 scout-repro 档进入统一凭据链（内部接口-11）：可复现运行（命令 + 退出码 0 + 输出摘要）并绑定 taskId/sourceRevision/mode/产物处置（内部规则-8）。
3. 交付时一并标注处置说明（写在哪里、何时清理）；在对话记录中明示「本产物为 disposable，未经毕业不得并入主干」。

## 边界与禁止项

- 禁止 disposable 产物在无显式毕业的情况下并入主干（B-M9-3）——想保留就走 scout 元技能的毕业移交（scout-graduate）。
- 用户中途改变主意要长期维护 = 场景切换：回 workflow 路由表重新判定，按全量方法论补规格。
