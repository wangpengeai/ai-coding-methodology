# spike-run：探针执行

在 explore 模式下回答「能不能成/可不可能」。产出是答案，不是要保留的代码。

## Safety Floor（不可降级，内部决策-008）

探针可简化的是**测试面**（验证=可复现运行），不可简化的是安全底线：默认禁生产凭据与生产数据（用合成/脱敏数据）、禁部署与共享分支写入、禁不可逆外部副作用；网络与外部写须用户显式授权；临时凭据/数据须有清理或撤销证据。

## 流程

1. 用两三句话写明：要回答的问题 + 打算怎么试。向用户点明这是探针。
2. 以满足正确性的最低成本去探；允许简化、硬编码、跳过边界——这些都是探针的合法形态。
3. 报告结论与建议。

## 一次性纪律

- 过程中写下的任何代码都标注为一次性，不并入主干。
- 探针代码想保留 = 新任务：重新分级（brainstorming 三档）并独立过批准门，禁止「顺手留下」。
- 完成声称以 scout-repro 档进入统一凭据链（内部接口-11）：可复现运行（命令+退出码 0+输出摘要）并绑定 taskId/sourceRevision/mode/产物处置；verification → code-review 流程保留，gate 不得将其报告为 full（内部规则-8）。

## 边界

- 探针阶段禁止顺手实现正式功能——那是 plan-execution 的活，越界即触发路由表重新判定。
- 探针暴露的 bug 按报 bug 处理：回路由表命中 root-cause-debugging 行。
