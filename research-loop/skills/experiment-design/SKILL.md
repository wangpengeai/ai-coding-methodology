# experiment-design：CS 实验设计（决策树与致命错误清单）

能回答什么问题，在设计期就定了型；混杂一旦埋进结构，事后分析无从挽回。本 skill 承载设计期的决策树与陷阱清单，产出接进 `research-hypothesis` 的预注册卡「实验设计」字段。

## 适用场景

- 用户显式表达实验设计意图：消融、基准对照、种子选择、运行序规划。
- 与算法迭代的分界＝目的判据（同研究假设行）：改进实现 → algo-loop；产出知识 → 研究环。
- 存在进行中获批准计划时计划优先。

## 置顶致命错误：伪重复

**同一 checkpoint、同一测试集的多次评估不是独立样本。** 重复测量的是同一个实现的同一次抽样，把「同一模型评 10 次」当 n=10 会系统性高估置信度。独立重复的单位＝被随机化的对象：换种子重新训练是重复；同一模型重跑评估不是。任何样本量声明先回答「独立单元是什么」。

## 设计决策树（CS 场景）

从问题出发选结构，不从熟悉的设计出发：

- **要在少数候选方案间做对照挑选？**
  - 各方案独立施测、环境可控 → 对照实验，运行序打乱。
  - 有已知扰动源（机器、时段、库版本）→ **区组**：把扰动圈进同一块内比较，块与块之间随它漂。
  - 同一对象可先后跑遍各方案（如同一环境依次试各配置）→ **交叉（交替轮转）**：留意上一条件的残留影响，条件间留足间隔。
- **拆解多因素的贡献（消融）？**
  - 因素少（≤4）→ **全析因**：主效应＋交互全可估，轮数 2^k。
  - 因素多 → 一次一部件（保留基线逐个去）：便宜但交互不可估；**部件消融的差值≠部件贡献**（交互被吃进差值），结论措辞要如实。
- **种子与重复层级**：种子的随机化单位是训练过程（或初始化），不是评估；报告效应时应给跨种子分布（均值＋离散），不给单种子点值。
- **运行序**：批内顺序固定会让「时间」与「条件」混杂（热身、缓存、机器状态漂移）——顺序随机化或至少交替排列，并记录序。
- **基准选择**：基准覆盖面要与结论的适用域一致；对单一基准的最优化不能外推为一般结论（基准过拟合作为竞争解释回到假设侧排除）。

## 产出与接口

- 产出＝实验设计说明（结构、因素、种子数与重复层级、运行序、区组方案），填入预注册卡「实验设计」字段。
- 样本量与统计功效的定量判定属后续阶段的统计机械面，本 skill 只给结构定性约束（如「至少跨 N 种子」的 N 留给判据协商）。

## 边界与禁止项

- 禁止自建场景判定表（判定唯一性在 workflow 路由表）。
- Stage 1 纯文本＋清单：可复现随机化与析因矩阵的生成属后续阶段，不内嵌脚本。
- 边界指针：公开基准的使用先自查其许可与引用要求（合规引用）。
