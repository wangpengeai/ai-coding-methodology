# research-hypothesis：研究假设与预注册（研究环入口）

把「我注意到一个现象」变成「一组可判别的候选解释」，并在决定验证的那一刻把判据钉死。本 skill 编排研究环的假设段；预注册卡模板在 `assets/prereg-card-template.md`（填好的卡为项目所有文件，本插件不解析）。

## 适用场景

- 用户显式表达科研问题/假设检验/预注册意图（产出对外有效结论或实验证据）。
- 与算法迭代的分界＝目的判据：为改进实现/产品指标 → 归 workflow 路由表算法迭代行（algo-loop）；为产出对外有效的知识 → 本行。两可时向用户澄清，不猜。
- 存在进行中获批准计划时计划优先（plan-execution 行）。

## 发散半段（零表单、零文件义务——对话即媒介）

研究的问题空间需要脑洞：以下四步不产生任何文件义务，鼓励多生成、保留少数派解释、不过早收敛。

1. **冻结观察**：先写观察再写解释——记录测量或来源、观察对象与范围、不确定性；措辞用「报告了/观察到/关联了」，不用因果语言（因果结论属于实验设计之后的推断）。观察是否在查看结果之后才形成，如实标注。
2. **框定研究问题**：把观察收窄成一个可回答的问题——对象、条件、要判别的差异。问题值不值得问，看答案能否改变后续决策。
3. **生成竞争解释**：对同一观察列出至少三个**候选**解释，从以下六类里找（CS 场景特化，不必每类都有、不强求对称）：
   - 真实效应（差异真的存在）
   - 测量噪声（指标本身的波动）
   - 环境与版本漂移（依赖、硬件、配置在两次观察间变了）
   - 种子运气（随机性导致的单次偏差）
   - 数据泄漏（评估面混入了训练面信息）
   - 基准过拟合（对特定评测集的针对性拟合，泛化不成立）
   全部标注「候选」。这一步的纪律是**多想**而不是筛——淘汰发生在预测判别之后，不发生在想象之前。
4. **推判别性预测**：每个候选解释推出至少一个「若它为真则应观察到 X」的可区分预测。两个解释推不出任何可区分预测时，说明问题框定还太粗，回到第 2 步。

**强推断的局限（明示）**：把清单上的竞争解释逐一排除，也只是收窄了范围——没进清单的解释、失准的辅助前提、残留的测量误差，任何一项都还可能翻案。结论只能说「在已检验的竞争解释范围内得到支持」。

## 收敛半段（唯一重纪律点）

用户决定验证某个假设时，落一张**预注册卡**（复制 `assets/prereg-card-template.md` 到项目内填写）：

- 判据在跑实验**之前**落定：指标、比较方式、**最小值得行动的差**（小于它的差异按噪声处理）、决策规则；
- 竞争解释登记为必填段（上一步的六类清单里保留哪些、各自如何排除）；
- 实验设计接 `experiment-design` skill 产出（消融/种子/运行序）；
- 数据接触声明如实填写——落卡时是否已见过结果，是后续解读结论的边界；
- 修订＝追加新卡，**不覆盖原判据**。

预注册卡之外不设任何强制产物：纯对话式的研究讨论不产生文件义务。卡填好后的实验执行归项目侧工具链（本插件不参与、不解析实验数据）。

## 与其他 skill 的接口

- 实验设计：预注册卡的「实验设计」字段接 `experiment-design` 产出（互引指针，非判定关系）。
- 完成声称：研究结论的验证仍走 verification → code-review（证据含预注册卡与判据对照）。
- 工程化下游：验证成立且要转入实现优化的，回 workflow 路由表算法迭代行（algo-loop）。
- learnings：收尾时按惯例提示记一条（允许显式跳过）。

## 边界与禁止项

- 禁止自建场景判定表（判定唯一性在 workflow 路由表）。
- 禁止解析实验数据或内嵌统计计算（统计机械面属后续阶段；本 skill 只承载纪律）。
- 禁止强制产物（发散半段零表单；收敛半段仅预注册卡一处，且为项目所有）。
- 边界指针：使用公开数据集/基准前自查数据许可与隐私边界（合规引用）。
