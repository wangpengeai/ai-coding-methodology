# research-loop 插件

研究环纪律插件（套件第六插件，可选安装）：把科研假设工作变成「发散自由、收敛单点从严」的研究环——竞争解释生成、判别性预测、预注册卡（跑前钉死判据，防事后归因）与 CS 实验设计决策树。域锚定＝算法研究/计算机科学/软件工程（内部决策-047）；与算法迭代（algo-loop）的分界＝目的判据（改进实现 → algo-loop；产出对外有效结论 → 本插件）。

## 环境要求

- 受支持宿主之一即可运行：原生形态＝ZCode 约定（`.zcode-plugin/` 清单＋skills 目录）；DSH（DeepSeek Harness）经 `dsh plugin ... add link` 运行时接入，MCode（MiniMax Code）/Kimi Code 经套件适配层安装（详见根 README「选择宿主」表）。
- Node.js ≥21（与根 README/内部未决-15 单源口径一致；测试用 Node 内置 runner；本插件 Stage 1 零运行时脚本、零钩子、零状态目录——轻状态形态）。
- 零第三方包依赖（套件级纪律，内部非功能需求-1）。

## 两个 skill

- `research-hypothesis`（入口）：发散半段（冻结观察/研究问题/竞争解释六类/判别性预测，零表单零文件义务）＋收敛半段（决定验证时落预注册卡，唯一重纪律点）。
- `experiment-design`：CS 特化设计决策树（消融/区组/交叉/种子与重复层级/运行序），伪重复陷阱置顶；产出接预注册卡「实验设计」字段。

场景判定唯一入口在 workflow 路由表（研究环两行）；插件未安装时路由两行仍命中并输出可行动安装指引（本插件 skill 不可执行），安装指引见套件根 README。

## 预注册卡

`assets/prereg-card-template.md` 为唯一模板（插件内单一事实源）；复制到项目内填写，填好的卡为**项目所有文件、插件不解析**。八字段（冻结观察/研究问题/候选假设＋竞争解释/判别性预测/判据与最小值得行动的差/实验设计/数据接触声明/修订留痕）；修订＝追加新卡不覆盖原判据。产物一律可选——纯对话研究零文件义务。

## 约束

- 域锚定红线（机器可查，check-repo-consistency 第 20 块）：插件资产禁临床/IRB/生物安全/双用途/物理计量类内容——「非全行业通用」为持久设计红线；仅保留薄边界指针（数据隐私/基准许可自查）。
- D1 纪律梯度：发散零摩擦、收敛单点从严；永不自动激活（无状态锚、纯显式意图触发）。
- 禁止解析实验数据或内嵌统计计算（统计机械面属 Stage 2，spike 前置）；禁止自建场景判定表。

## 先验复审义务（内部决策-047 决策 8）

本插件形态系先验设计（零实战验证）。**首个真实科研任务完成后**，按实战发现走 spec-writing 回流修订本插件规格（skills 结构/模板字段/边界措辞）；跨会话悬空时按 内部接口-8 登记 OPEN-n。本义务在插件 README 与批交付报告双登记。
