# verify-gate 声明式完成闸（Stop hook）

项目里显式声明"本轮结束前必须通过什么验证"，闸才生效；没声明的项目零影响。
概念借鉴 gstack（MIT © Garry Tan），自写实现。规格：`内部规格 内部模块-8` 内部规则-3/4、T-M8-2/3。

## 声明文件格式

在**项目根**创建 `verify.gate`，每行一条验证命令：

```text
# 井号开头的整行是注释，空行忽略
npm test
npm run lint
```

- 命令执行 shell 按四级探测：`VERIFY_GATE_SHELL` 环境变量整体覆盖 > PATH 内 `bash` > Windows Git 惯例安装位置 > 系统 shell 兜底（Windows 为 cmd.exe 语义）；前三级按 `bash -c` 执行，工作目录为项目根。从 turn 结束时的 cwd 逐级向上找到首个含 `verify.gate` 的目录即视为项目根。
- 逐条顺序执行，**任一退出码非 0 即阻断本轮结束**（Stop 阻断），输出 JSON 摘要含失败命令、退出码、输出前 5 行。
- 行内 `#` 不是注释（避免误伤含 `#` 的命令）；只识别整行注释。
- 单条命令默认 20 秒超时（内置超时，跨平台恒可用），可用环境变量 `VERIFY_GATE_CMD_TIMEOUT` 覆盖；超时按退出码 124 报告。

## 信任存储机制（防篡改，2026-09-19 评审修复 B13 语义）

- 声明内容（过滤注释/空行后的**命令流**）**首次出现**时，把其 sha256 基线记录到**用户级**信任存储 `<homedir>/.zcode/verify-gate-trust/<项目根路径摘要>.sha256`——信任脱离项目分发面，仓库无法预置伪造信任（`WF_TRUST_DIR` 环境变量可覆盖存储目录）。
- 首次发现**当次不执行命令**：阻断一拍并提示人工核对声明内容（其中命令将在后续每次 Stop 执行）；下一次触发起按基线比对。
- 此后每次触发都比对：不符，或信任文件存在但空/不可读（完整性无法证明）→ 提醒"声明文件已变更，请重新确认"并阻断，**不会静默继续**执行其中的命令。
- 按命令流而非文件原始字节做哈希：行尾（CRLF/LF）与注释排版变化不算篡改；改了要执行的命令才需要重新确认。
- 重新确认方式：人工审阅声明内容后**删除上述用户级信任文件**（不是项目根文件），下次运行按当前内容重新首录（首录当次仍不执行）。
- 项目根 `.verify-gate.trust` 为旧版遗留——**一律不采信**（含内容正确的文件：与 verify.gate 同源预置的"匹配"不构成来源证明），可安全删除。

## 启用 / 停用

- 启用：在项目根创建 `verify.gate` 并写入验证命令，无需其他配置。
- 停用：删除 `verify.gate`（可顺手删用户级信任文件与项目根旧版遗留）。未声明项目此 hook 空输出退出 0，零影响。
- 临时绕过单条命令的超时限制：`VERIFY_GATE_CMD_TIMEOUT=<秒>`。

## 可靠性姿态

- fail-open：脚本自身异常（执行 shell 探测失败、信任文件无法落盘等非声明逻辑故障）一律静默退出 0，不阻断宿主。
- 阻断输出走严格 JSON schema：`hookSpecificOutput.{hookEventName:"Stop", additionalContext}` + 退出码 2。
- 自检：`node workflow/hooks/verify-gate.mjs --selftest`（四态 + fail-open 注入，全 PASS 退出 0）。
