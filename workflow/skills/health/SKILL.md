# health：代码质量健康评分（只读体检，不动代码）

把项目已有的检查工具跑一遍，按固定权重的评分卡算出 0-10 分，与上次评分对比给趋势。工具是项目自己的工具，本 skill 只负责探测、运行、计分与记录——分数是镜子不是扳手：发现问题列清单交用户决策，不在本 skill 里修。

## 适用场景

- 用户显式要求："做一次健康检查""项目质量怎么样""跑一遍检查"。
- 周期节点：路由表周期节点行（与 `retro`/`learnings` 并列），按用户意图命中本 skill。
- 想知道质量是在改善还是在滑坡：单次评分加历史趋势回答这个问题。
- 不适用的场合：完成声称前的证据聚合归 verification，代码评审归 code-review；本 skill 是周期性只读体检，不参与"是否完成"的判定。

## 流程

### 第 1 步：工具栈检测

探测项目实际配置的检查工具，探测到什么、探测不到什么都如实呈现：

| 检查类 | 探测对象（示例） |
|---|---|
| 类型检查 | tsconfig.json 与 tsc、mypy 配置等 |
| 测试 | package.json 的 test 脚本、pytest、cargo test、go test 等 |
| lint | eslint / biome / ruff 等配置文件 |
| 其余 | 构建命令可运行性、README 等文档存在性等基础项 |

- 探测手段：读项目配置文件与命令可用性探测；用户在项目内声明过的检查命令优先于自动探测，照声明执行，不二次猜测。
- **未配置不是失败**：项目没配的工具如实标注"未配置"——不扣分也不加分，其权重按比例分摊给已配置的分项；不因"没配 lint"惩罚一个根本不写该语言的项目。

### 第 2 步：运行与取证

- 逐个运行检测到的命令，顺序执行（工具可能共享资源或锁文件）；每个命令记录退出码、耗时、输出摘要。
- 错误与警告计数从工具原始输出解析（按各工具的错误行模式统计），不凭印象估数。
- 运行失败（命令存在但执行报错）是真实的质量信号，按失败计分；与"未配置"严格区分，两者不得混写。

### 第 3 步：加权评分卡（规格固定值）

| 分项 | 权重 |
|---|---|
| 类型检查 | 22 |
| 测试 | 28 |
| lint | 18 |
| 其余（构建可运行性、文档存在性等基础项） | 32 |

- 权重合计 100，是规格固定值（内部规则-4 沿用原值），不按项目自行调参。
- 每分项按 0-10 打分，加权合计折算为 0-10 总分（保留一位小数）：总分 = Σ(分项得分 × 权重) ÷ 100。
- 分项基准：退出码 0 且零告警记满分；问题少量降档、大量低档（如类型检查零错误 10 分、个位数错误 7 分档、数十错误 4 分以下——档位按实际计数落，不许朝好看的方向凑）。
- 诚实计分：测试全过但类型错误成堆的代码库不能拿高分——分数要反映现实，不是安慰。

### 第 4 步：输出与历史记录

- **输出**：总分 + 逐项明细表（分项、得分、权重、工具命令、退出码、问题摘要）；得分落后的分项列出原始输出的关键行，让用户不必重跑就能行动。
- **历史追加**：项目内 `.context/health-history.jsonl`，每行一次评分 JSON——日期、总分、各分项得分（未配置的分项记 null）。
- **趋势对比**：读历史最后一行与本次对比——总分升降，哪些分项退步；退步分项对照本次工具输出指出新出现的问题。首次运行无历史时明说"首次检查，暂无趋势，下次运行起可对比"。

## 与其他 skill 的接口

- 上游：workflow 路由表周期节点行（与 `retro`/`learnings` 并列）；用户显式触发或周期到达，进入条件由路由表判定。
- verification：分界——那边是完成声称前的证据聚合（证据先运行），这边是周期性体检评分；两边的运行记录互不替代、互不引用。
- retro：分界——质量趋势的数字归本 skill 的历史记录，会话与流程维度的复盘归 retro。
- 对外契约无 IF（反向边界的直接体现）：探测与运行只发生在项目内，不触碰规格目录。

## 边界与禁止项

- **只读**：探测配置与运行检查命令之外，不改任何代码；发现的问题列清单交用户，修复归后续任务，不在本 skill 内动手。
- 权重为规格固定值：类型检查 22 / 测试 28 / lint 18 / 其余 32；调整评分卡是规格修订，不是使用技巧。
- 历史存项目内（B-M6-2）：`.context/health-history.jsonl` 随版本库走，禁止项目外路径，不外发。
- **禁止写 `.sdd/` 与 `docs/plans/`（B-M6-1，反向边界）**：评分历史不进 spec-gate 受检文档集（内部规则-5）。
- 未配置不扣分：把"项目没配某工具"当扣分项即违反第 1 步的探测纪律。
