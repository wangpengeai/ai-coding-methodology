# learnings：项目学习记录（各流程收尾提示的承接方）

把散落在会话里的经验变成项目内可检索的资产。载体是项目根的 `经验记录`——一条经验一行、一句话说完、带证据链接；开始新任务前按场景检索一遍，让过去的踩坑替未来的任务探路。记录与检索之外的事（趋势、指标、复盘评价）一律不在本 skill。

## 适用场景

- 各流程 skill 正常结束时承接收尾提示（T-M6-2）：idea-review、plan-execution、root-cause-debugging、verification 等正常收尾时提示"记一条 learning"，提示的承接方是本 skill；允许"无收获"跳过，但跳过要显式说出口，不是沉默略过。
- **写入时点（C6/内部任务-193）**：learnings 须在本任务 verification 签发前写（冻结前）；verification 签发后源码桶任何写入都会使完成链失配，之后只允许下一任务开头补记；finalize 后 Stop 提醒仅作遗漏信号，不回写历史任务。
- 开始新任务前检索同场景经验：进入一个流程前查 `经验记录` 里该场景的既有条目，把命中项带入任务上下文。
- 用户显式要求查看、检索学习记录（路由表周期节点行）。
- 不适用的场合：复盘分析归 retro，健康评分归 health；进入条件由路由表判定，本 skill 不自定义。

## 流程

### 记录载体

项目根 `经验记录`，Markdown 列表，一行一条经验：

```
- YYYY-MM-DD | 场景 | 一句话经验 | 证据链接
```

- **日期**：记录当天的 `YYYY-MM-DD`。
- **场景**：经验发生时的流程场景（调试、计划评审、执行、验证、工具链等），供按场景检索命中；工具链=任务中发现的插件/工具自身缺陷观察，按本纪律记一句话+证据即可（结构化缺陷登记仍走 OPEN-n，不在此）。
- **一句话经验**：项目特性、命令坑、陷阱或模式，一句话说完（上限见记录纪律）。
- **证据链接**：指向提交、文件或走查记录；确无证据时显式写"无"。可空，但空必须以"无"的形态显式存在——空着是让读者猜，"无"是明说。

文件不存在则创建后追加，存在则在末尾追加；常规记录只追加、不改写既有行——历史记录是当时的事实，修正靠追加新条目，不靠改旧账。既有行的改写只有一条合法通道：**定期梳理**（见下节），不经随手修订。

### 定期梳理（内部规则-11）

经验记录 规模必须受控——无界增长会钝化检索并让过时判据冒充现行经验。梳理要素：

- **触发**：①条目数超过阈值（机械承载＝仓库 lint 规则 `learnings-size`，缺省 150，超标即违例）——记录动作碰到提醒即触发一轮梳理；②retro 周期节点捎带（周期复盘时顺带过一遍）。
- **四动作（内部任务-117 扩三为四），触发后全量处置**——每一条目四择一，「其余 N 条保留原样」类批量豁免非法：
  - **保留**：仍有独立判别力的可迁移判据原样保留（disposition 表记族名与一句理由）。
  - **并入同族**：同主题多条并成一条综合判据（保留族内最早日期与最新证据链接，互补要点收拢；合并条目为新写文本，族内原条目出清）。
  - **归档（内部任务-117 新增）**：真实发生但判据迁移价值已耗尽的历史实录（批操作记录、已关闭 OPEN 的调查链、被后续机制取代的流程描述）**逐字迁入** `经验归档` 对应批次节——零改写、零删除、不计入 `learnings-size` 阈值；归档是低成本高保真的收敛通道，禁止以删除替代归档来压条数。
  - **删除**：仅限三判据——所载坑已被结构性修复且判据无迁移价值、纯会话流水账（装机/下架/发布操作实录）、被新条目完整取代，三者居其一即删。删除不删证据：git 历史与各条目的证据指针仍在。
- **留痕（守恒算式强制）**：梳理记录落当批任务的内部证据目录（按任务分目录，不随源码公开），必须含**逐条 disposition 全表**（每条一行：保留+族名+理由／并入族#N／归档／删除+依据；删/并附原文或「日期｜场景｜首句摘要」+ git 提交可达引用——梳理前快照即本批提交的父提交，`git show <提交>^:经验记录` 逐字可取，两者等价满足「删除不删证据」）与**条目守恒算式**（梳理前条数 ＝ 保留 ＋ 并族出清 ＋ 归档 ＋ 删除）；经验记录 本身保持纯条目，不混入梳理元数据。`经验归档` 形态：项目根、按梳理批次分节（`## 归档批 YYYY-MM-DD（任务号，迁出 N 条）`）、条目逐字保留，与 经验记录 同为 内部决策-039 归档资产类。

梳理后核对 learnings-recap 钩的交互：被出清任务号的已 finalize 任务会重新触发「补一条」提醒——梳理时对这些任务号预置 reminded 册（写入钩的状态文件），避免执行代理照提醒回写刚清掉的条目。

### 记录纪律（B-M6-3）

- **无实际经验不记**：没踩过的坑、没验证过的"收获"，不产生条目；本流程无收获是合法且常见的结论，收尾时明确回答"无收获，跳过"。
- **一句话上限**：每条经验一句话（内部规则-3）；写不进一句话，说明还没想清楚，想清楚再来记。
- **禁止编造**：经验必须来自本次流程的真实经历，证据链接必须真实存在或显式写"无"；为"显得有收获"硬凑条目比没有条目更糟——它污染的是未来任务的检索结果。

### 查询用法

- 开始新任务前，按即将进入的场景检索 `经验记录` 的同场景条目；命中即读，带入任务。
- 命中是线索不是结论：条目只有一句话，适用前提要对照当前项目状态复核——半年前的坑可能已被修复，当时的绕法可能已是今天的陷阱。

### 各 skill 收尾衔接（T-M6-2 承接方）

- "每个 workflow skill 正常结束时提示记一条 learning"是全局约定（T-M6-2），本 skill 是该约定的唯一承接方：各 skill 收尾提示，记录的载体、纪律与检索用法归本 skill 定义。
- 提示保持轻量：收尾时一句话提示即可，不展开成独立流程；中断或失败结束的流程不提示——约定只覆盖"正常结束"。
- 自察记录（内部决策-019）是 learnings 的素材源之一：triage 确认的自察异常若沉淀出真实经验，按本 skill 纪律记录（一句话 + 证据链接指向 `内部工作流状态` 条目或排查 commit）；无收获显式跳过，不硬凑。

## 与其他 skill 的接口

- 上游：一切 workflow 流程 skill 的正常收尾提示（T-M6-2）；路由表周期节点行与 `retro`/`health` 并列，按用户意图命中。
- retro：分界——本 skill 存取一条条经验，不做复盘分析；指标、趋势与证据锚定的评价归 retro，两边产出互不替代。
- health：分界——健康评分与评分历史归 health；`经验记录` 只装经验条目，不混入评分数据。
- 对外契约无 IF（反向边界的直接体现）：本 skill 读取项目内文件与提交信息，不提供也不消费任何 spec-gate 接口。

## 边界与禁止项

- **禁止写 `.sdd/` 与 `docs/plans/`（B-M6-1，反向边界）**：学习记录的唯一落点是项目根 `经验记录`；它不进 spec-gate 受检文档集（内部规则-5），也不以任何形式写入规格目录。
- 不做复盘分析：会话指标、趋势对比、经验之外的系统性评价归 retro，本 skill 只管记录与检索。
- 存储形态限定（B-M6-2）：项目内 Markdown 文件，随版本库走；禁止项目外路径与私有格式存储。
- 记录纪律违例即条目无效（B-M6-3）：超一句话上限、编造证据、无经验硬凑，发现即删该条目。
