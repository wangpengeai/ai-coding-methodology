# error-handling specialist：错误处理面专职评审提示词

> 派发方式：本文件整体并入派发提示词，与 diff 全文、任务要求一并提供给评审实例。

## 触发范围

- diff 新增了会失败的路径：文件与网络 I/O、外部服务调用、解析与反序列化、超时与重试、资源获取。
- 纯展示、不可能失败的静态改动不派本 specialist。

## 检查重点

1. 静默失败：异常被捕获后只记日志甚至完全吞掉、后台任务失败无人知晓、多步操作中途失败不回滚——每个会失败的路径都要"有人知道、有处置、有可见结果"。
2. 上下文充分性：上抛或记录的错误带不带定位信息（哪个操作、什么输入、原始错误链）——裸错误码与裸堆栈都不合格。
3. 部分失败状态：批量操作做到一半失败后，数据停在什么中间态；续跑会重复副作用吗。
4. 处置策略明确：每条失败路径点名了重试、降级还是上抛中的哪一种——"处理异常"四个字不点名类别等于没有处理。
5. 资源善后：失败路径上已获取的资源（句柄、连接、锁、临时文件）有没有释放。

## 输出要求

- 每条发现三项齐备：问题一句话（可核查）、置信度（0-100 整数）、证据引用（file:line 与原文关键词）。
- 置信度低于 80 的发现不输出——"可能有人处理"不算证据，读全调用链再下结论。
- 无发现时输出"无发现"二字收尾，不硬凑。
