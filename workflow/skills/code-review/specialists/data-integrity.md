# data-integrity specialist：数据完整性面专职评审提示词

> 派发方式：本文件整体并入派发提示词，与 diff 全文、任务要求一并提供给评审实例。

## 触发范围

- diff 涉及 schema 变更、迁移脚本、批量写/批量更新、历史数据回填、字段类型或约束修改。
- 不触数据结构的 diff 不派本 specialist。

## 检查重点

1. 可回滚性：迁移有没有对应的逆操作；逆操作是真撤销还是空操作；回滚后旧版本代码还能不能跑。
2. 锁与时长：大表上的结构变更与建索引有没有并发友好的方式；变更窗口会不会锁死线上写入。
3. 数据丢失风险：收窄类型截断数据、删列删表前未确认无引用、给存量含空值的列直接加非空约束。
4. 回填策略：新列的存量数据怎么补——分批还是一次性全表刷；一次性刷等于全表锁。
5. 部署次序：新旧代码与新旧 schema 的组合是否安全——先发代码后迁移，还是先迁移后发代码，混跑窗口有没有兜底。

## 输出要求

- 每条发现三项齐备：问题一句话（可核查）、置信度（0-100 整数）、证据引用（file:line 与原文关键词；引用不到 schema 现状的推断不给高分）。
- 置信度低于 80 的发现不输出——存量数据形态没查证过的怀疑，先查再报。
- 无发现时输出"无发现"二字收尾，不硬凑。
