# code-review 检查清单

## 使用说明

- 评审对象是本次 diff（未暂存改动 + 分支相对基线的改动），逐条对照下表；每条意见按 ≥80 置信度协议带 0-100 评分与证据引用（file:line + 原文关键词），低于 80 的发现先补证再评，补不上即丢弃。
- 两遍法：第一遍只过 **CRITICAL**（最高严重级，数据损坏、安全漏洞、生产故障级别），第二遍过 **HIGH** 与 **NORMAL**。
- 类别在本次 diff 无涉及时记"无发现"，不硬凑；清单之外 diff 里真实存在的问题照报——清单是下限不是上限。
- 条目要求 diff 外取证的（如枚举新值追消费方），用只读工具真去追，不在 diff 内部猜。
- 噪音类问题（顺手重构、无关格式改动、投机抽象）不进本清单，按 code-discipline 负向清单在派发前预检。

## CRITICAL（可能造成数据损坏、安全漏洞或生产故障）

| 检查点 | 判定线索 |
|---|---|
| SQL 注入与参数化 | 查询语句出现字符串插值或拼接变量（哪怕变量先做了类型转换）即命中；合格形态是参数绑定/预编译。 |
| 竞态与并发修改 | 先查后写无原子性保障（check-then-set）、find-or-create 无唯一约束兜底、状态迁移不用条件更新——并发下会产生重复或跳跃。 |
| 不可信输入信任边界 | 外部输入（用户提交、回调、模型生成内容）未经格式/类型/形状校验就入库、拼 URL、进邮件、进文件路径——外部内容默认不可信。 |
| Shell 与命令注入 | 命令执行以字符串拼接构造、或对不可信内容做动态求值；合格形态是参数数组调用。 |
| 资源泄漏 | 打开的句柄、连接、锁、临时文件在错误路径上没有释放——finally/defer/close 缺失，异常一路抛出后资源悬空。 |
| 鉴权缺失 | 新增入口（路由、端点、命令）没有身份校验、或默认放行拒绝缺失；改一个 id 就能读到别人资源的越权路径。 |
| 枚举与取值完整性 | diff 新增枚举值/状态/类型常量时，未逐个核对全部消费方（分支语句、过滤数组、展示层）——新值落到错误的默认分支即故障。 |

## HIGH（很可能引发缺陷或返工）

| 检查点 | 判定线索 |
|---|---|
| 静默失败 | 异常被捕获后仅记日志甚至吞掉、后台任务失败无告警、多步操作中途失败无回滚——失败发生时"没人会知道"。 |
| 边界与空值 | 零、负数、空集合、单元素、上界、超长输入、首末项在分支里没有着落——只在极值出错的逻辑缺陷。 |
| N+1 查询 | 迭代块内出现逐条查询/请求，可合并为一次批量取数——数据量上来后线性放大为性能故障。 |
| 异步上下文阻塞 | 事件循环/异步函数内出现同步 I/O、长睡眠、无界 CPU 计算——一个请求拖死整条并发链路。 |
| 错误响应不一致 | 新增错误路径的响应格式与既有约定不同、状态码与错误类型不匹配、错误信息泄漏内部细节（栈、SQL、路径）。 |
| 类型边界漂移 | 值跨语言/跨层传递时类型未归一（数字与字符串互变）——哈希、序列化、判等的结果随类型漂移而错。 |
| 破坏性变更 | 删改既有字段、参数、返回结构、事件载荷而无兼容层或版本策略——消费方在升级时被打断。 |

## NORMAL（可维护性与一致性）

| 检查点 | 判定线索 |
|---|---|
| 死代码与孤儿引用 | 赋值未读、导入未用、本次改动使其失去全部引用的定义仍留在 diff 外——自己造成的孤儿按 code-discipline 必须清理。 |
| 魔数与散落字面量 | 逻辑中的裸数字阈值/上限/重试次数、同一字面量在多文件重复出现——该收敛为命名常量或配置。 |
| 文档与注释同步性 | 本次 diff 触及的注释与实现是否同步（计数/枚举类写死数字、失效说明首当其冲）；仓内文档（README/仓库维护说明/工具 README）是否需随行为变化同变更单元更新而未更新；生成物/只读产物说明是否缺「改它的正确路径」或同步责任；公开槽（description/帮助文案）是否违反受众纪律——判定口径以 doc-discipline 七条款为准（纪律七·受众分层：公开说明先功能/条件/限制/动作，内部编号不作前提；机械面=check-repo-consistency public-metadata 组）。本行已覆盖 diff 触及面；下面两行只查 diff 之外的存量陈旧。 |
| 注释与代码漂移 | 注释描述的行为在本次 diff 之后已不成立——注释还在讲旧故事。 |
| 文档与示例陈旧 | diff 改变了文档描述的行为、接口签名、配置项或默认值，但对应文档/示例未同步——读者照旧文档操作会失败。 |
| 命名与风格一致性 | 同一概念在新代码里换了名字、与相邻模块的既有风格脱节——遵循所在文件的既有写法优先于个人偏好。 |
| 测试结构缺陷 | 测试间共享可变状态、依赖执行顺序、依赖系统时钟/时区、断言无序结果的顺序——重跑即飘的测试是负资产。 |
| 提交内容越界 | diff 混入与任务无关的格式化、重排、顺手重构（对照 code-discipline 负向清单）——污染评审范围与回溯。 |
