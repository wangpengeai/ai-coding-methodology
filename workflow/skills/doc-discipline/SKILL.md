# doc-discipline：文档与代码注释纪律（执行期随行）

七条随行纪律，管"文档与注释写什么、谁负责保持同步"。凡写/改代码或归档文件即生效。

## 适用场景

- 随行 skill，不是入口：不开场、不路由，跟随一切写/改代码或归档文件的场合——计划执行中、缺陷修复中、评审返工中、收尾移交中。
- 与 code-discipline 的分工：code-discipline 管"改多少"与"用什么改"（含"别乱改别人的注释"的负向禁令）；本 skill 管正面规则——注释该怎么写、文档什么时候必须更新、谁负责保持同步。两者并行生效、互不替代。
- 生效对象：代码注释与**归档文件**（跨任务跨会话的事实源：`specs/`、`.sdd/` 受检文档、权威台账、README/仓库维护说明、经验记录）。**过程文件**（`docs/plans/*`、任务简报、进度台账）豁免本 skill 行文条款——它允许工作痕迹，只需守住"不是事实源"（元技能全局规则的过程/归档分界条）。

## 流程：七条纪律

### 纪律一：注释解释「为什么」而非「是什么」

- 注释写意图、约束、坑与出处（为什么这么做、为什么不能改），不复述代码本身在做什么——代码自己会说话。
- 与实现同步是硬义务：你的改动使既有注释失效时，同一改动内更新注释，不留"实现已变、注释滞后"的残骸。

### 纪律二：计数/枚举类表述是高危失效面

- "11 类消息""会报两项 FAIL""全绿门在步骤 23"这类写死数字与状态的表述，实现一变即成谎言（2026-10-05 缺陷诊断实测：同一任务内 README、项目约定文件与测试注释三次自相矛盾）。
- 能由机器校验的不写死数字（改为指向校验命令或生成物）；必须写时注明口径与同步责任（谁在哪类改动里必须更新它）。

### 纪律三：生成物/同步物/只读产物写明修改路径与同步责任

- 生成物、vendored 副本、契约同步物、只读产物的说明必须写清两件事：**改它的正确路径**（经什么命令或流程复现）与**谁负责保持同步**。
- 禁止让读者从只读产物直接下手改——说明里没有修改路径的产物，视同没有主人的隐患。

### 纪律四：仓内文档与代码同一变更单元内更新

- 行为、命令、计数、状态变了，README/仓库维护说明/工具 README 等仓内文档与代码在同一提交或同一 PR 内更新，不允许"实现变了、文档滞后一轮"。
- 拿不准某文档是否受本次改动影响时，宁可花一分钟核对，不留给下一个读者去撞。

### 纪律五：语言一致，不混写

- 中文文档写中文注释，英文实现写英文注释；同一份文件内不中英混写（代码标识符与命令除外）。

### 纪律六：过程文件豁免，归档文件全条款

- 过程文件（计划、评审记录、执行台账、证据、DEBUG REPORT）允许工作痕迹，不适用纪律一/四/五的行文要求。
- 归档文件适用全部条款；向归档文件写入内容必须经移交动作（逐条登记 + 过程文件回写标注去向），不把过程内容随手复制进事实源。

### 纪律七：受众分层

- 按主要读者与用途分层：公开选择说明（面向普通使用者）、操作诊断（面向操作者）、维护契约（面向维护者）、审计记录（面向复核者）、**外部合同交付（甲方/外部接收方，内部决策-062 第五类）**；同一文件可按字段或章节分层，不互斥。
- **外部合同交付面**（内部决策-062 D9 / 内部模块-26）：按合同最小交付集写法——只含合同侧字段与可验收判据；禁止内部任务号、内部路径、评审记录与开发流水；引用目标必须在交付包内（不得悬空），交付文档由投影工具生成而非手抄。定界：公开选择说明面向使用者与市场，外部合同交付面向合同接收方与审计对象。
- **公开生效面**：插件/技能/命令的 description 元数据与公开帮助（README 首屏、市场文案、宿主展示位）属受众纪律生效面——先说明功能、适用条件、限制与动作，禁止用内部开发编号（ADR/IF/需求条目号等）或开发流水代替解释；删编号不得丢准确触发语义（「—— 触发条件：…」结构保留）。
- 维护者契约与诊断标识可保留（合法出处），但须顺带解释所指；出处置于解释之后，不作第一句前提。
- 机器分工：公开槽位的确定性检查由 `scripts/lib/public-metadata.mjs`（check-repo-consistency 第 16 块）承载——只拦公开字段中的内部编号，正文/诊断/注释/规格不在扫描面；「受众是否自足」的语义评审仍归人。

## 与其他 skill 的接口

- code-discipline：分工声明——它管"改多少/用什么改"（含负向禁令），本 skill 管文档与注释的正面规则；执行期并行生效。
- code-review：检查单「文档与注释同步性」项以本 skill 七条款为判定口径（含纪律七·受众分层；checklist.md 引用，不内置第二份条款）。
- plan-execution / branch-finishing：随行引用与收尾移交义务分别以其正文为准；本 skill 不承载移交判据（义务全文唯一载体在 branch-finishing）。

## 边界与禁止项

- 不含任何测试与验证内容：怎么验证归 tdd 与 verification。
- 不约束过程文件行文（纪律六）；不把条款扩张为格式洁癖（空行/引号风格归 code-discipline 的"遵循文件既有风格"）。
- 不定义进入条件：凡写/改代码或归档文件即生效，与路由表无关。
